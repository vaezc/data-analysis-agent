# 2 分钟 Demo 脚本

目标：先让面试官看到产品可用，再用 30 秒把工程深度兜住。不要一上来讲架构，先跑通一个真实问题。

## Demo 前准备

- 打开 Live Demo 或本地 `http://localhost:3000`
- 登录一个已验证账号
- 准备走内置「销售数据」demo，避免现场上传文件网络或格式出意外
- 浏览器 DevTools 可以不开；如果面试官追问，再展示 Network 里的 SSE

## 0:00-0:20 开场定位

> 我先用 2 分钟演示一下这个项目。它解决的是一个很常见的问题：业务同学手里有 CSV 或 Excel，但不会写 SQL，也不想打开 BI 工具配置一堆字段。所以这里的目标是，把自然语言问题变成可追溯的数据分析过程。

操作：打开首页，点左侧「销售数据」demo。

## 0:20-0:45 提第一个问题

> 我用内置销售数据，问一个最基础的问题：哪个区域销售额最高？注意右侧不是一次性吐答案，而是 Agent 会先看数据结构，再决定怎么计算。

操作：输入：

```text
哪个区域销售额最高？请生成柱状图
```

观察点：

- 左侧数据集被选中
- 消息区出现 `inspect_data` / `run_analysis` / `create_chart`
- 最终回答包含具体数值和图表

## 0:45-1:15 解释可追溯性

> 这里我最想强调的是可追溯性。传统 chat demo 很容易只给一个答案，但用户不知道数字怎么来的。我把 Agent 的每一步都流式展示出来：先 inspect schema，再由二级 LLM 生成 SQLite SQL，最后用 better-sqlite3 在内存库里执行。这样每个数字来自真实计算，不是模型编出来的。

如果图表已出现，补一句：

> 适合可视化的数据，Agent 会主动调 create_chart，所以业务用户不用知道要选 bar chart 还是 pie chart。

## 1:15-1:35 展示报告能力

> 再演示一个更偏交付的场景：让它生成一份可以发给别人的分析报告。

操作：输入：

```text
基于刚才的销售结果，生成一份简短报告
```

观察点：

- 出现 `generate_report`
- 报告卡片可下载 HTML

讲法：

> 报告是独立 HTML，图表会以内嵌 SVG 的形式放进去，所以下载后离线双击也能看。这是面向非技术用户的小细节。

## 1:35-2:00 收束工程亮点

> 背后我做了几件工程化的事：第一，SSE 流式协议，工具步骤、文本、图表、报告都用统一事件推到前端；第二，数据层从最早的内存 Map 迁到了 Prisma + Postgres，解决 Vercel Serverless 跨函数不共享内存的问题；第三，加了 Auth.js 和 owner check，A 用户访问不到 B 用户的数据；第四，SQL 沙箱只允许 SELECT/WITH，并且每次用独立 `:memory:` 数据库。

最后一句收口：

> 所以它不是一个 prompt demo，而是一个可以解释清楚数据流、安全边界和部署取舍的 Agent 应用。

## 被打断时的 15 秒版

> 一句话：上传 CSV，用自然语言问问题，Agent 会流式展示看结构、跑 SQL、出图、写报告的每一步。核心亮点是我自己实现了 tool-calling 主循环，SQL 在 SQLite 内存沙箱里真实执行，数据和会话用 Prisma + Postgres 持久化，并且做了登录和 owner check。
